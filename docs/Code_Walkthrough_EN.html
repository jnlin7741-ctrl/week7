A01 / State and v-model

A ref holds reactive state in Vue.

ref(null)

No user is known on the first render.

Walkthrough and reasoning

v-model connects an input to a ref. The App template binds email, password, title, and content. In script code a ref uses .value, while templates can refer to user or title directly. A plain variable can hold a value, but assigning it does not provide the same reactive tracking. All account state here belongs to the current page session.

Typing changes a ref. Vue updates the affected screen.

A02 / The request helper

A helper centralizes repeated request behavior.

Options

Default method GET; optional JSON body.

Headers

Accept describes the expected response.

Token

Only a protected call receives Authorization.

frontend/src/api.js

export async function request(path, { method = 'GET', body, protectedCall = false } = {}) {
  const headers = { Accept: 'application/json' }
  if (body !== undefined) headers['Content-Type'] = 'application/json'
  // Attach the token only to a protected request.
  if (protectedCall && accessToken) headers.Authorization = `Bearer ${accessToken}`
  const response = await fetch(`/api${path}`, {
    method, headers, body: body === undefined ? undefined : JSON.stringify(body),
  })

Walkthrough and reasoning

Destructuring gives names to the options and supplies defaults. body === undefined avoids sending a body for GET. JSON.stringify converts an object into bytes represented as text. The request uses a relative /api path, which works through the local proxy and on the production origin. This function returns a Promise.

request('/me', { protectedCall: true }) becomes GET /api/me.

// Tokens stay in memory. Reloading the page requires another sign-in.
let accessToken = ''
export function setToken(value) { accessToken = value }
export function clearToken() { accessToken = '' }
export async function request(path, { method = 'GET', body, protectedCall = false } = {}) {
  const headers = { Accept: 'application/json' }
  if (body !== undefined) headers['Content-Type'] = 'application/json'
  // Attach the token only to a protected request.
  if (protectedCall && accessToken) headers.Authorization = `Bearer ${accessToken}`
  const response = await fetch(`/api${path}`, {
    method, headers, body: body === undefined ? undefined : JSON.stringify(body),
  })
  if (response.status === 204) return null
  const data = await response.json().catch(() => ({}))
  if (!response.ok) {
    if (response.status === 401 && protectedCall) {
      clearToken()
      window.dispatchEvent(new Event('session-expired'))
    }
    const error = new Error(data.message || `Request failed (${response.status}).`)
    error.status = response.status
    throw error
  }
  return data
}

A03 / Await and HTTP errors

fetch resolves for HTTP error responses, so code must inspect the status.

204

Return null without JSON parsing.

!response.ok

Handle a non-2xx response.

401

Remove the token and notify the interface.

Walkthrough and reasoning

await waits for the Promise inside the async function. It does not block the entire browser. fetch rejects for network failures, but a 400 or 403 normally resolves to a Response. The helper converts these HTTP failures into thrown errors so the caller’s catch can display a message. A protected 401 also dispatches session-expired.

A 403 is an HTTP response, not automatically a fetch exception.

        if (password.getBytes(StandardCharsets.UTF_8).length>72)

        // Store a password hash. Never store the original password.

    }

        boolean matches=passwords.matches(input.password(),found.map(u->u.passwordHash).orElse(dummyHash));

            JwsHeader.with(MacAlgorithm.HS256).build(),claims)).getTokenValue();
