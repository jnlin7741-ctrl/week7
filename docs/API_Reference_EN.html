Request examples

Registration

{"name":"Alex","email":"alex@example.com","password":"PracticeOnly123!"}

Login

{"email":"alex@example.com","password":"PracticeOnly123!"}

Create or replace editable post content

{"title":"Study group","content":"Library at 3 PM."}

Do not send ownerId, id, createdAt, or version. The backend controls those fields.

Response models

UserView = { id, name, email }
LoginResult = { accessToken, tokenType, expiresIn, user }
PostView = { id, ownerId, title, content, createdAt, updatedAt }
ErrorView = { code, message }

Validation rules

  • Name: nonblank, at most 60 Java characters.
  • Email: required email format, at most 254 characters, normalized to lowercase for lookup and storage.
  • Registration password: at least 12 characters, at most 72 UTF-8 bytes. Login does not apply the signup minimum again.
  • Title: nonblank, at most 120 characters. Content: nonblank, at most 4,000 characters.
  • Unknown JSON fields and malformed UUID path values return 400.

Authentication lifecycle

The API uses a signed HS256 token with subject, issuer, issued-at time, and a 30-minute expiry. The decoder verifies signatures and claims. The frontend keeps the token in memory. Reload and sign-out clear that browser token. The API has no token-revocation endpoint or refresh-token flow.

Example error

{"code":"FORBIDDEN","message":"Only the author can change this post."}

Use HTTP status for broad behavior and code/message for useful feedback. A 204 response has no body. A network failure can happen before an HTTP response arrives.

Local data versus deployed data

Local uses H2 in backend/data. Production uses Neon PostgreSQL with the same migration. Register cloud accounts separately. A frontend reload changes page state but does not remove database records.
